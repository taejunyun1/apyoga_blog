# 이전 작성 기록 삭제 기능 설계

작성일: 2026-07-14
상태: 사용자 승인(개별 삭제 + 전체 삭제, 확인 후 영구 삭제)

## 배경

홈 화면의 `최근 작성 기록`에는 완료한 콘텐츠가 브라우저 IndexedDB에 남아 있지만, 현재는 기록을 열어보는 기능만 있고 사용자가 직접 정리할 방법이 없다. 완료 기록은 `history` 테이블뿐 아니라 해당 콘텐츠를 다시 여는 데 사용하는 `drafts` 테이블과 연결 이미지가 저장된 `images` 테이블에도 걸쳐 있으므로, 삭제 시 관련 데이터를 일관되게 제거해야 한다.

## 목표

- 최근 작성 기록을 한 건씩 삭제할 수 있다.
- 최근 작성 기록 전체를 한 번에 삭제할 수 있다.
- 영구 삭제 전에 대상과 개수를 명확하게 확인한다.
- 기록을 삭제하면 연결된 초안과 이미지 데이터도 함께 제거한다.
- 작성 중인 임시 글은 전체 기록 삭제의 영향을 받지 않는다.
- 삭제 성공과 실패를 화면에서 바로 알 수 있다.

## 제외 범위

- 휴지통이나 삭제 후 되돌리기는 제공하지 않는다.
- 삭제 기록을 서버에 보관하거나 복구하지 않는다.
- 여러 기록을 체크박스로 골라 삭제하는 선택 모드는 추가하지 않는다.
- 작성 중인 글의 기존 폐기 흐름은 변경하지 않는다.

## 사용자 흐름

### 개별 삭제

1. 사용자가 홈의 최근 작성 기록 행 오른쪽 삭제 버튼을 누른다.
2. `“기록 제목” 기록을 삭제할까요?` 확인창이 열린다.
3. `취소`를 누르면 아무 데이터도 변경하지 않고 확인창을 닫는다.
4. `삭제`를 누르면 버튼을 비활성화하고 삭제를 실행한다.
5. 성공하면 해당 행을 제거하고 `기록을 삭제했어요` 토스트를 표시한다.
6. 실패하면 행을 유지하고 오류 메시지를 표시한다.

### 전체 삭제

1. 기록이 한 건 이상일 때 `최근 작성 기록` 제목 옆에 `전체 삭제` 버튼을 표시한다.
2. 버튼을 누르면 `저장된 기록 N개를 모두 삭제할까요?` 확인창이 열린다.
3. `삭제`를 누르면 완료 기록과 연결 데이터만 모두 삭제한다.
4. 성공하면 빈 상태 문구로 전환하고 `모든 기록을 삭제했어요` 토스트를 표시한다.
5. 실패하면 기존 목록을 유지하고 오류 메시지를 표시한다.

## 화면 설계

- 기존 기록 행의 제목·날짜·화살표 구조를 유지한다.
- 행 전체를 하나의 링크로 감싸는 대신, 기록을 여는 링크와 삭제 버튼을 같은 행 안의 독립된 조작 요소로 분리한다.
- 삭제 버튼에는 휴지통 아이콘과 접근 가능한 이름을 제공한다.
- 제목을 누르면 기존처럼 해당 기록으로 이동하고, 삭제 버튼 클릭은 이동을 발생시키지 않는다.
- 섹션 제목 줄 오른쪽에 작은 `전체 삭제` 버튼을 둔다. 기록이 없으면 표시하지 않는다.
- 확인창은 현재 화면 스타일에 맞춘 모달로 제공한다. 제목, 대상 설명, `취소`, 위험색 `삭제` 버튼으로 구성한다.
- 확인창은 `role="alertdialog"`, 제목과 설명 연결, `취소` 버튼 초기 포커스, Escape 닫기, 배경 클릭 닫기를 지원한다. 삭제 처리 중에는 중복 실행을 막는다.
- 모바일에서는 기록 정보가 줄어들 수 있지만 삭제 버튼은 최소 터치 영역을 유지하고 링크와 겹치지 않는다.

## 데이터 설계

저장소에 다음 작업을 추가한다.

- `deleteHistory(id)`: 트랜잭션 안에서 지정한 `history` 행, 같은 ID의 `drafts` 행, 해당 `draftId`를 가진 `images` 행을 삭제한다.
- `clearHistory()`: 현재 `history`의 ID 목록을 읽고, 트랜잭션 안에서 해당 이력·초안·이미지만 일괄 삭제한다.

전체 삭제는 `drafts` 테이블 전체를 비우지 않는다. `history`에 포함된 ID만 대상으로 삼아 완료되지 않은 작성 중 초안을 보존한다.

스토어는 저장소 삭제가 성공한 뒤에만 메모리의 `history` 목록을 갱신한다. 개별 삭제는 해당 ID를 제거하고, 전체 삭제는 빈 배열로 바꾼다. 저장소 오류가 나면 기존 목록을 그대로 유지한다.

## 상태 및 오류 처리

- 홈 화면은 현재 삭제 대상, 개별·전체 삭제 유형, 처리 중 상태, 오류, 토스트 메시지를 관리한다.
- 삭제 처리 중 확인창의 취소·삭제 버튼을 비활성화해 중복 요청을 막는다.
- 성공한 뒤 확인창과 오류를 정리하고 완료 토스트를 표시한다.
- 실패하면 확인창을 유지해 사용자가 다시 시도하거나 취소할 수 있게 한다.
- 토스트는 `role="status"`, 오류는 `role="alert"`로 알린다.

## 테스트 전략

구현은 테스트 주도 방식으로 진행한다.

1. Dexie 저장소 테스트에서 개별 삭제가 이력·초안·연결 이미지를 함께 제거하는 실패 테스트를 먼저 작성한다.
2. 전체 삭제가 완료 기록 데이터만 제거하고 작성 중 초안을 보존하는 실패 테스트를 작성한다.
3. 스토어 테스트에서 성공 시 목록 갱신과 실패 시 기존 목록 보존을 검증한다.
4. 홈 컴포넌트 테스트에서 개별·전체 삭제 확인창, 취소, 성공 토스트, 오류 상태를 검증한다.
5. 모바일과 데스크톱에서 기록 열기와 삭제 버튼이 독립적으로 동작하는지 확인한다.
6. 전체 타입 검사, 단위·컴포넌트 테스트, 빌드를 실행한다.
7. Cloudflare 배포 후 실제 운영 화면에서 개별 삭제와 전체 삭제를 확인한다.

## 완료 기준

- 사용자가 최근 작성 기록을 개별 또는 전체 삭제할 수 있다.
- 모든 영구 삭제는 확인창을 거쳐 실행된다.
- 삭제된 기록은 새로고침 후에도 다시 나타나지 않는다.
- 삭제된 기록의 연결 초안과 이미지가 남지 않는다.
- 전체 삭제 후에도 작성 중인 임시 글은 유지된다.
- 성공·실패 상태가 접근 가능한 메시지로 표시된다.
- 모바일과 데스크톱 모두에서 기록 열기와 삭제가 겹치지 않는다.
- 자동 테스트와 운영 환경 검증이 모두 통과한다.
