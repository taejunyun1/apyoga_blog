# AP YOGA 재작성 버튼 및 사진 매칭 개선 설계

작성일: 2026-07-14

## 목표

결과 화면의 재작성 버튼이 실제 문구를 의미 있게 변경하도록 만들고, 사용자가 버튼 주변에서 변경 결과와 처리 상태를 즉시 확인할 수 있게 한다. 또한 업로드한 사진을 작은 썸네일로 다시 보여 주어 네이버 문단 배치와 인스타그램 게시 순서를 한눈에 확인할 수 있게 한다.

## 확인된 원인

- 재작성 이벤트 연결과 저장은 동작하지만, `OpenAIProvider.rewriteSection()`이 원격 AI를 호출하지 않고 제한된 로컬 문구만 사용한다.
- `감성 줄이기`와 `최근 글과 다르게`는 버튼보다 위에 있는 도입부·제목을 변경한다. 본문 재작성도 긴 텍스트의 끝부분을 바꾸므로 현재 스크롤 위치에서는 변화를 확인하기 어렵다.
- 모든 재작성 버튼이 처리 중에도 활성 상태이며, 완료 알림이 모두 `문구를 변경했어요`로 같아 어떤 영역이 바뀌었는지 알기 어렵다.
- 운영 화면에서 재작성 버튼의 계산된 커서는 `default`이며 관련 콘솔 오류는 없었다.
- 결과 데이터에는 네이버 `imagePlacements`와 인스타그램 `imageOrder`가 있지만, 현재 UI는 네이버 배치를 텍스트 목록으로만 보여 준다.

## 선택한 접근

원격 GPT 재작성을 기본으로 사용하고, 네트워크·응답 검증 실패 시 안전한 로컬 재작성으로 대체한다. 버튼 바로 아래에 변경된 결과 미리보기를 표시해 화면 밖에서 바뀌는 문제를 해결한다. 사진은 별도 매칭 컴포넌트로 분리해 두 채널에서 같은 업로드 이미지 데이터를 재사용한다.

UI 피드백만 추가하는 방식은 실제 재작성 품질을 해결하지 못하고, 로컬 재작성만 확장하는 방식은 반복 클릭 시 표현 다양성이 제한되므로 채택하지 않는다.

## 재작성 데이터 흐름

1. `RewriteActionSheet`가 채널, 영역, 지시문을 전달한다.
2. `StudioView`가 현재 요청 키를 저장하고 모든 재작성 버튼을 잠근다. 클릭한 버튼은 `변경 중…`으로 표시한다.
3. 스토어가 `AIProvider.rewriteSection()`을 호출한다.
4. `OpenAIProvider`는 같은 출처의 `POST /api/content/rewrite`로 요청한다.
5. Pages Function은 인증 미들웨어 뒤에서 입력 크기와 허용 채널·영역을 검사하고 OpenAI에 구조화된 재작성 결과를 요청한다.
6. 원격 응답이 실패하거나 형식·안전·길이 검증을 통과하지 못하면 `LocalAIProvider`로 한 번 대체한다.
7. 스토어는 기존 문구와 다른지 확인하고 후보 결과의 게시 전 검토를 계산한다. 검증을 통과한 후보만 반영하고 저장하며, 검토나 저장이 실패하면 이전 문구로 되돌린다.
8. 성공한 재작성 결과를 호출자에게 반환한다. `StudioView`는 영역별 완료 토스트와 버튼 아래 미리보기를 갱신한다.

## API 계약과 검증

요청은 `channel`, `section`, `instruction`, `currentText`, `memo`, `avoid`, `tone`만 포함한다. 이미지 바이너리, 썸네일 URL, 계정 정보는 전송하지 않는다.

응답은 다음 구조를 사용한다.

```json
{
  "source": "openai",
  "data": {
    "section": "body",
    "text": "변경된 문구"
  }
}
```

서버와 클라이언트에서 다음 조건을 검사한다.

- 요청한 영역과 응답 영역이 같아야 한다.
- 결과는 공백을 제외하고 기존 문구와 달라야 한다.
- 네이버 본문 재작성은 500자 이상이어야 한다.
- 해시태그 재작성은 공백으로 구분된 `#` 문구만 허용한다.
- 원격 결과에서 금지 표현이나 의료적 단정이 발견되면 로컬 대체를 시도한다. 최종 후보도 안전 검토를 통과하지 못하면 기존 문구를 보존하고 오류를 표시한다.
- 요청 본문 크기 제한과 same-origin JSON 검사는 기존 콘텐츠 생성 API와 같은 정책을 따른다.

## 버튼 상태와 변경 결과 표시

- 모든 활성 `<button>`은 호버 시 `cursor: pointer`를 사용하고 비활성 버튼은 `cursor: not-allowed`를 사용한다.
- 재작성 중에는 모든 재작성 버튼을 비활성화해 동시 요청과 저장 순서 충돌을 막는다.
- 클릭한 버튼만 `변경 중…` 문구를 표시한다.
- 완료 토스트는 `도입부의 감성을 줄였어요`, `본문의 철학적 표현을 줄였어요`, `사진 설명을 보강했어요`, `새 제목을 만들었어요`처럼 구체적으로 표시한다.
- 버튼 영역 바로 아래에 최근 변경 영역과 변경된 문구 미리보기를 표시한다. 긴 본문은 몇 줄로 제한하되 원본 편집 영역에는 전체 결과를 반영한다. 미리보기는 변경이 발생한 채널에서만 표시하고 채널을 전환해도 해당 채널의 마지막 결과를 유지한다.
- 실패하면 성공 토스트나 미리보기를 갱신하지 않고 기존 문구를 유지하며 상단 오류 배너에 이유를 표시한다.

## 사진 매칭 UI

`ResultImageMap` 컴포넌트가 `StudioImage[]`와 채널별 배치 정보를 받는다.

### 네이버

- `imagePlacements`를 문단 번호 순으로 정렬한다.
- 각 카드는 썸네일, `문단 N 뒤`, 사진 설명을 표시한다.
- `imageId`가 없는 경우 카드 자리를 유지하고 `사진을 불러올 수 없어요`를 표시한다.

### 인스타그램

- `imageOrder` 순서대로 썸네일 카드를 표시한다.
- 각 카드에 `1번째`, `2번째`처럼 게시 순서를 표시한다.
- `coverImageId`와 같은 카드에는 `대표 사진` 배지를 표시한다.

데스크톱에서는 자동 열 수의 카드 그리드, 모바일에서는 한 장 이상이 보이는 가로 스크롤 목록을 사용한다. 썸네일은 편집 결과에 저장된 `thumbnailUrl`만 사용하며 원본 사진을 새로 업로드하거나 외부로 전송하지 않는다.

## 컴포넌트 경계

- `RewriteActionSheet`: 버튼 렌더링, 요청 이벤트, 로딩·비활성 상태만 담당한다.
- `ResultImageMap`: 이미지 ID와 썸네일을 결합해 채널별 매칭 카드를 렌더링한다.
- `ResultEditor`: 채널 결과, 이미지 목록, 최근 재작성 미리보기를 조합한다.
- `StudioView`: 재작성 요청 상태, 영역별 토스트, 오류와 미리보기 상태를 관리한다.
- `studio-store`: 재작성 결과 검증, 결과 반영, 안전 검토, 저장을 원자적인 순서로 수행한다.
- `OpenAIProvider`와 Pages Function: 원격 재작성과 로컬 대체 경계를 담당한다.

## 오류 처리

- 원격 실패는 로컬 재작성이 성공하면 사용자에게 오류로 노출하지 않고 정상 결과로 처리한다.
- 원격과 로컬이 모두 실패하면 기존 문구를 보존하고 오류 배너를 표시한다.
- 저장 실패 시 변경 완료 토스트를 표시하지 않는다.
- 매칭되는 썸네일이 없어도 전체 결과 화면은 유지하고 해당 카드만 대체 상태를 표시한다.

## 테스트 및 검증

구현은 실패 테스트를 먼저 작성한 뒤 진행한다.

- Functions 단위 테스트: 입력 검증, OpenAI 성공, 재시도·실패, 동일 문구, 본문 500자, 해시태그 형식.
- Provider 단위 테스트: 원격 성공, 잘못된 응답의 로컬 대체, 요청 데이터 최소화.
- Store 단위 테스트: 변경 영역 반영, 안전 검토와 저장, 실패 시 기존 문구 보존.
- 컴포넌트 테스트: 로딩·비활성 버튼, 구체적인 이벤트, 네이버·인스타그램 썸네일 카드와 누락 이미지 상태.
- E2E: 재작성 버튼 클릭 후 실제 문구·토스트·미리보기 변경, 모든 버튼의 포인터 커서, 모바일 가로 썸네일과 데스크톱 그리드.
- 전체 Vitest, Functions·Vue 타입 검사, 프로덕션 빌드, 모바일·데스크톱 Playwright를 실행한다.
- 배포 후 운영 URL에서 페이지 식별, 빈 화면·프레임워크 오류, 콘솔 상태, 버튼 상호작용, 썸네일 렌더링을 다시 확인한다.

## 범위 제외

- 사용자가 결과 화면에서 사진 순서를 다시 편집하는 기능.
- 썸네일을 눌러 원본 크기 모달을 여는 기능.
- 문단 사이에 실제 이미지를 삽입하는 리치 텍스트 편집기.
- 사진을 서버에 장기 저장하거나 외부 스토리지로 전송하는 기능.
