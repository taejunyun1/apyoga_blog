# 제목·본문 함께 재작성 및 저장 후 메인 이동 설계

## 목표

결과 화면의 `최근 글과 다르게` 액션이 제목만 바꾸는 현재 동작을 제목과 네이버 본문을 함께 바꾸는 동작으로 확장한다. 재작성 결과는 사진 분석 내용과 기존 글의 맥락을 유지하면서 최근 결과와 다른 흐름으로 생성하고, 네이버 본문 500자 기준과 콘텐츠 안전 규칙을 계속 만족해야 한다.

결과 화면 하단의 저장 동작은 사용자가 한 번에 이해할 수 있는 `작성 이력에 저장하고 메인으로` 버튼으로 제공한다. 저장에 성공했을 때만 메인으로 이동하고, 메인 화면에서 저장 완료 토스트를 표시한다.

## 확정된 범위

- `최근 글과 다르게`는 현재 선택된 네이버 제목과 네이버 본문을 한 번에 재작성한다.
- 도입부, 해시태그, 수업 안내, 사진 배치와 사진별 캡션은 그대로 유지한다.
- 재작성 본문은 공통 콘텐츠 브리프의 사진 설명·분위기·핵심 감각을 참고한다.
- 사진 장면을 설명문처럼 나열하지 않고, 확인된 분위기와 감각을 발행 가능한 감성 문장으로 풀어낸다.
- 제목과 본문 중 하나라도 검증 또는 저장에 실패하면 둘 다 기존 값으로 되돌린다.
- 결과 화면 하단에서 작성 이력 저장과 메인 이동을 하나의 명확한 동작으로 제공한다.
- 기존의 다른 부분 재작성 액션과 상단 홈 아이콘은 유지한다.

## 재작성 구조

기존 단일 영역 재작성 계약은 `감성 줄이기`, `철학 줄이기`, `사진 분위기 더하기`와 인스타그램 액션을 위해 그대로 둔다. 제목·본문 동시 변경에는 별도의 구조화 계약을 추가한다.

클라이언트 AI 포트는 다음 입력과 출력을 사용한다.

```ts
interface RewriteNaverTitleAndBodyInput {
  currentTitle: string
  currentBody: string
  instruction: string
  memo: string
  photoContext: string
  avoid: string
  tone: Tone
}

interface RewriteNaverTitleAndBodyOutput {
  title: string
  body: string
}
```

OpenAI 어댑터는 `/api/content/rewrite`에 `kind: "naver-title-body"`인 구조화 요청을 한 번 보낸다. 서버는 제목과 본문을 같은 응답에서 생성하는 전용 JSON Schema를 사용한다. 이 방식은 제목과 본문의 흐름을 일치시키며, 두 번의 요청 중 한쪽만 성공하는 부분 성공 상태를 만들지 않는다.

네트워크 오류, 서버 오류 또는 원격 응답 검증 실패 시 로컬 제공자의 제목·본문 묶음 재작성을 사용한다. 로컬 제공자도 결과 묶음 전체를 반환하며 스토어는 검증이 끝나기 전까지 화면 상태를 변경하지 않는다.

## 입력과 사진 맥락

스토어는 현재 선택된 제목인 `titles[0]`, 현재 본문, 메모, 금지 표현, 네이버 톤과 콘텐츠 브리프를 묶어 AI 제공자에 전달한다. `photoContext`는 다음 확인된 정보만 포함한다.

- 전체 분위기
- 본문에서 다룰 감각과 수련 초점
- 사진별 분석 설명
- 사용자 메모 요약

원본 이미지와 base64 데이터는 재작성 API로 보내지 않는다. 이미 사진 분석 단계에서 확정된 텍스트 브리프만 사용해 요청 크기와 개인정보 노출을 줄인다.

## 검증과 원자성

서버, OpenAI 어댑터, 스토어의 경계에서 다음 규칙을 검증한다.

- 제목과 본문은 공백이 아니어야 한다.
- 새 제목은 현재 제목과 달라야 한다.
- 새 본문은 현재 본문과 달라야 한다.
- 새 본문은 앞뒤 공백을 제외하고 최소 500자여야 한다.
- 제목과 본문에 사용자 금지 표현과 의료적 단정이 없어야 한다.
- 본문은 사진 번호, `사진 속`, `이미지에서`처럼 장면을 직접 중계하는 표현을 사용하지 않아야 한다.
- 재검토 결과에 기존에 없던 의료적 단정이 생기지 않아야 한다.

스토어는 기존 네이버 결과, 검토 결과와 수정 시각을 먼저 스냅샷으로 보관한다. 응답 전체 검증, 제목·본문 적용, 검토 갱신, 저장이 모두 성공한 뒤에만 새 결과를 확정한다. 어느 단계에서든 실패하면 제목과 본문을 포함한 결과 상태 전체를 스냅샷으로 복구한다.

## 화면 동작

`최근 글과 다르게` 버튼은 기존 위치와 이름을 유지한다. 처리 중에는 모든 부분 재작성 버튼과 편집 입력을 비활성화하고, 해당 버튼에 `최근 글과 다르게 변경 중…` 및 `aria-busy="true"`를 표시한다.

성공하면 제목 라디오 목록의 첫 항목과 본문 편집 영역이 즉시 새 값으로 갱신된다. 최근 변경 미리보기에는 다음을 함께 표시한다.

- `최근 변경 · 새 제목과 본문`
- 새 제목 전체
- 새 본문의 앞부분 미리보기

미리보기 본문은 화면을 지나치게 길게 만들지 않도록 시각적으로 줄 수를 제한하되, 실제 본문 편집 영역에는 500자 이상의 전체 결과가 반영된다. 성공 토스트는 `제목과 본문을 새롭게 만들었어요`를 표시한다. 실패하면 기존 제목과 본문을 유지하고 기존 오류 배너에 실패 이유를 표시한다.

결과 화면 하단의 기존 `작성 이력에 저장` 버튼은 `작성 이력에 저장하고 메인으로`로 바꾼다. 클릭하면 다음 순서로 동작한다.

1. 중복 클릭을 막기 위해 버튼을 비활성화한다.
2. 현재 초안을 작성 이력에 저장한다.
3. 저장에 성공하면 메인으로 이동한다.
4. 메인 화면에서 `작성 이력에 저장했어요` 토스트를 표시한다.
5. 저장에 실패하면 결과 화면에 그대로 머물고 오류를 표시한다.

메인 토스트는 URL의 일회성 쿼리 신호를 읽어 표시한 뒤 쿼리를 제거한다. 새로고침으로 같은 토스트가 반복되지 않게 한다.

## 접근성 및 모바일

- 모든 버튼은 기존 전역 버튼 커서 규칙을 사용하고 비활성화 상태를 명확히 표시한다.
- 재작성 처리 상태는 버튼 문구, `aria-busy`, 토스트로 전달한다.
- 최근 변경 미리보기와 저장 완료 토스트는 `aria-live="polite"`로 알린다.
- 하단 저장·이동 버튼은 모바일에서 최소 터치 영역과 전체 너비를 유지한다.
- 본문 편집 영역의 기존 모바일 자동 확대 방지 설정을 유지한다.

## 테스트 전략

구현은 테스트 주도 방식으로 진행한다.

1. 서버 OpenAI 요청 테스트에서 제목·본문 전용 구조화 스키마와 사진 맥락 프롬프트를 검증한다.
2. 서버 응답 검증 테스트에서 500자 미만 본문, 같은 제목·본문, 금지 표현, 사진 중계 표현을 거부하는지 확인한다.
3. OpenAI 어댑터 테스트에서 한 번의 요청으로 제목·본문을 읽고, 잘못된 응답과 네트워크 오류 시 로컬 묶음 결과로 대체하는지 확인한다.
4. 스토어 테스트에서 제목과 본문이 함께 변경되고 저장되는지, 검토 또는 저장 실패 시 둘 다 복구되는지 확인한다.
5. 결과 컴포넌트 테스트에서 버튼 성공 후 제목과 본문 및 묶음 미리보기가 함께 바뀌는지 확인한다.
6. 저장 후 이동 테스트에서 저장 성공 때만 메인으로 이동하고 메인 토스트가 한 번 표시되는지 확인한다.
7. 전체 타입 검사, 단위·컴포넌트 테스트, 프로덕션 빌드와 브라우저 회귀 테스트를 실행한다.
8. Cloudflare Pages에 배포한 뒤 실제 로그인 환경에서 재작성과 저장 후 메인 이동을 확인한다.

## 완료 기준

- `최근 글과 다르게` 한 번으로 현재 네이버 제목과 본문이 모두 바뀐다.
- 새 본문은 500자 이상이며 사진 브리프와 연결된 감성적 발행 문장이다.
- 도입부, 해시태그, 수업 안내와 사진 배치는 바뀌지 않는다.
- 재작성 실패 시 제목과 본문이 부분적으로 바뀌지 않는다.
- 최근 변경 영역에서 새 제목과 본문 변경을 함께 확인할 수 있다.
- 하단 버튼으로 작성 이력 저장과 메인 이동이 한 번에 완료된다.
- 저장 실패 시 메인으로 이동하지 않는다.
- 메인에서 저장 완료 토스트가 한 번만 표시된다.
- 자동 테스트와 Cloudflare 운영 검증이 통과한다.
