# A.P YOGA Content Studio MVP Design

## 1. 문서 목적

이 명세는 `AP_YOGA_Content_Studio_4Docs_v7`의 네 문서를 구현 가능한 하나의 MVP로 축소한다. MVP의 목적은 사용자가 iPhone Safari 또는 데스크톱 브라우저에서 사진과 짧은 메모를 입력하고, 얼굴을 가린 뒤, 네이버 블로그와 인스타그램용 콘텐츠를 한 번에 생성·수정·복사하는 핵심 흐름을 실제로 검증하는 것이다.

MVP는 외부 자격 증명이 없어도 로컬에서 전체 흐름이 동작해야 한다. 동시에 AI와 Cloudflare 저장소를 나중에 연결할 때 화면과 도메인 로직을 다시 작성하지 않도록 포트와 어댑터 경계를 둔다.

## 2. 기준 문서와 우선순위 해석

다음 네 문서를 제품 요구사항의 기준으로 사용한다.

- `01_UX_Design_Flow_and_Icon_Spec.md`: 모바일 우선 UX, 얼굴 가림, 생성·복사 흐름, 상태 설계
- `02_Product_Feature_BrandMemory_Priority.md`: P0/P1/P2 범위, Brand Memory 정책
- `03_AI_API_Multichannel_Architecture.md`: 공통 브리프, 채널 출력, 부분 재작성, AI Provider 경계
- `04_Cloudflare_Data_Security_Operations.md`: Vue 3 PWA, 이미지 보안, Cloudflare 목표 구조, 삭제 정책

문서의 P0는 운영 인프라까지 포함해 한 번에 구현하기에는 범위가 크다. 이번 MVP는 P0 사용자 경험을 하나의 완전한 수직 흐름으로 제공하고, 실제 Cloudflare Access·D1·R2·OpenAI 연결은 동일 인터페이스를 사용하는 후속 어댑터로 분리한다.

## 3. 선택한 접근과 대안

### 선택: 로컬 기능형 수직 슬라이스

Vue 3 PWA에서 이미지 처리, 얼굴 가림 편집, 콘텐츠 생성, 부분 재작성, 자동 저장, 이력, 복사를 모두 체험할 수 있게 만든다. 기본 AI는 입력에서 결정론적 결과를 만드는 `LocalAIProvider`를 사용하고, 저장은 브라우저 저장소를 사용한다.

이 접근은 자격 증명 없이도 완성된 UX를 검증할 수 있고, 실제 AI나 Cloudflare 연결 전에도 오류 복구와 모바일 사용성을 테스트할 수 있다.

### 대안 A: 처음부터 전체 Cloudflare 배포형

Workers, D1, R2, Access, OpenAI를 한 번에 연결하면 운영 구조에 가장 가깝다. 그러나 계정·도메인·비밀키·비용 정책이 선행되어야 하고, 프런트 핵심 흐름보다 인프라 설정이 검증 속도를 늦춘다.

### 대안 B: 화면 전용 프로토타입

가장 빠르지만 업로드, 편집, 저장, 복사, 재작성 상태가 실제로 이어지지 않는다. 핵심 위험을 검증하지 못하므로 채택하지 않는다.

## 4. MVP 범위

### 포함

- 모바일 우선 단일 사용자 흐름
- 최대 10장 이미지 선택
- JPEG, PNG, WebP 업로드와 `heic2any`를 사용한 HEIC/HEIF 변환
- 브라우저 이미지 방향 보정, 리사이즈, 메타데이터가 제거된 새 Blob 생성
- MediaPipe Tasks Vision 얼굴 감지와 수동 얼굴 마스크 추가
- 블러, 흰색 원, A.P YOGA 스티커 마스크
- 마스크 이동, 크기 변경, 삭제, 실행 취소
- 마스크가 반영된 편집본만 후속 단계에 전달
- 사진 순서 변경, 대표 사진 선택, 사진 삭제
- 짧은 수련 메모, 꼭 포함할 내용, 피할 내용
- 네이버·인스타그램 글쓰기 방식과 톤 선택
- AI가 이해한 공통 콘텐츠 브리프 확인·수정
- 네이버와 인스타그램 결과 병렬 생성
- 채널별 부분 재작성
- 제목·본문·해시태그·전체 결과 복사
- 자동 임시 저장, 새로고침 후 복구, 작성 이력
- 이미지 5일 보관 만료 표시와 로컬 만료 정리
- 오프라인·부분 성공·오류·재시도 상태
- 제공된 앱 아이콘을 사용하는 설치 가능한 PWA

### 제외

- 실제 자동 게시
- 회원·강사 식별과 얼굴 개인 식별
- 실제 Google 로그인과 Cloudflare Access 정책
- 실제 D1/R2/OpenAI 호출과 운영 배포
- 승인 기반 Brand Memory 자동 후보화
- 음성 메모, 비용 대시보드, 캘린더, 데이터 내보내기
- Threads, 카카오채널, 릴스, 멀티테넌시

실제 인증과 서버 저장은 UI에 가짜 로그인 화면을 만드는 대신 개발 모드의 단일 사용자 세션으로 명시한다. 이 선택은 보안 기능이 구현된 것처럼 오해하게 하지 않는다.

## 5. 핵심 사용자 흐름

1. 홈에서 새 글을 시작하거나 임시 저장 글을 복원한다.
2. 사진을 최대 10장 선택한다.
3. 사진별 변환·압축 상태를 확인한다.
4. 자동 감지된 얼굴 또는 수동 추가 영역에 마스크를 적용한다.
5. 미확인 얼굴 경고를 확인하고 사진 순서와 대표 사진을 정한다.
6. 수련 메모와 채널별 글쓰기 방식·톤을 선택한다.
7. 로컬 AI가 만든 공통 브리프를 확인하고 필요하면 수정한다.
8. 네이버와 인스타그램 콘텐츠를 동시에 생성한다.
9. 각 채널의 결과를 선택하고 원하는 부분만 재작성한다.
10. 게시 전 확인 결과를 보고 채널별 콘텐츠를 복사한다.
11. 최종 결과와 메타데이터를 작성 이력에 저장한다.

사진 선택부터 생성 요청까지는 정상 흐름 기준 1분 이내를 목표로 한다. 사용자가 직접 입력해야 하는 항목은 짧은 메모와 필요한 수정으로 제한한다.

## 6. 화면 구조

### 홈

새 글 만들기, 작성 중인 글, 최근 작성 글, 이미지 만료 시간을 제공한다. 통계와 관리자 기능은 배치하지 않는다.

### 사진 준비

업로드 카드마다 변환·압축·완료·실패 상태를 보여준다. 성공한 사진은 유지하고 실패한 사진만 재시도한다.

### 얼굴 가림

상단에는 이전·완료, 중앙에는 편집 Canvas, 하단에는 가림 방식·얼굴 추가·실행 취소를 둔다. 자동 감지 미지원 환경에서도 수동 마스크 편집으로 흐름을 완료할 수 있다.

### 사진 구성

썸네일 목록에서 순서를 이동하고 대표 사진을 선택한다. AI 추천은 정보로만 표시하고 자동 확정하지 않는다.

### 메모와 톤

메모, 꼭 포함할 내용, 피할 내용, 글쓰기 방식, 채널별 톤을 한 화면의 짧은 폼으로 제공한다. 고급 설정은 숨긴다.

### 브리프 확인

수련 요약, 분위기, 신체 초점, 시각 키워드, 불확실한 주장 목록을 편집 가능한 칩과 입력으로 보여준다. 확인 이후에만 생성한다.

### 생성 진행

브리프 정리, 네이버 생성, 인스타그램 생성, 규칙 검수 단계를 표시한다. `Promise.allSettled` 의미의 독립 상태를 사용해 한 채널이 실패해도 다른 채널 결과를 보존한다.

### 결과

네이버와 인스타그램 탭을 분리한다. 네이버는 제목 후보, 도입 후보, 본문, 캡션, 해시태그를 제공하고 인스타그램은 첫 문장 후보, 긴 캡션, 짧은 캡션, 해시태그를 제공한다. 재작성과 복사 버튼은 결과의 해당 부분 가까이에 둔다.

## 7. 아키텍처

```text
Vue Views / Components
        ↓
Pinia Studio Store
        ↓
Use Cases
  ├─ PrepareImages
  ├─ BuildContentBrief
  ├─ GenerateChannels
  ├─ RewriteSection
  └─ SaveDraft / FinalizePost
        ↓
Ports
  ├─ AIProvider
  ├─ DraftRepository
  ├─ ImageRepository
  ├─ FaceDetector
  └─ ClipboardGateway
        ↓
Local Adapters (MVP)
  ├─ LocalAIProvider
  ├─ DexieDraftRepository
  ├─ DexieImageRepository
  ├─ MediaPipeFaceDetector + Manual fallback
  └─ BrowserClipboardGateway
```

화면 컴포넌트는 외부 API나 브라우저 저장소를 직접 호출하지 않는다. Store가 Use Case를 호출하고, Use Case가 타입으로 정의된 포트를 사용한다. 이후 `OpenAIProvider`, `D1DraftRepository`, `R2ImageRepository`를 추가해도 화면 계약은 유지한다.

구현 기술은 Vue 3, Vite, TypeScript, Pinia, Vue Router, VueUse, Dexie, Konva와 `vue-konva`, `browser-image-compression`, `heic2any`, MediaPipe Tasks Vision, `vite-plugin-pwa`, Vitest, Vue Test Utils, Playwright로 고정한다. 외부 디자인 패키지는 설치하지 않고 실제 Astryx 토큰이 제공될 때 교체 가능한 로컬 토큰을 사용한다.

## 8. 주요 도메인 계약

```ts
interface AIProvider {
  analyzeImages(input: AnalyzeImagesInput): Promise<ContentBrief>
  generateNaver(input: ChannelInput): Promise<NaverOutput>
  generateInstagram(input: ChannelInput): Promise<InstagramOutput>
  rewriteSection(input: RewriteInput): Promise<RewriteOutput>
  review(input: ReviewInput): Promise<ReviewOutput>
}
```

`ContentBrief`, `NaverOutput`, `InstagramOutput`은 기준 문서의 JSON 구조를 그대로 출발점으로 삼는다. UI가 임시 문장 조각에 의존하지 않도록 모든 생성 결과는 구조화된 타입으로 반환한다.

`StudioDraft`는 현재 단계, 이미지 메타데이터, 마스크 데이터, 메모, 채널 설정, 브리프, 생성 결과, 오류 상태, 생성 시각을 보유한다. 원본 파일은 영구 저장하지 않고 메타데이터가 제거된 편집본만 저장한다.

## 9. 이미지와 개인정보 처리

- 원본 이미지는 서버로 전송하지 않는다.
- 브라우저가 디코딩한 픽셀을 새 Canvas에 그린 뒤 편집본 Blob을 만든다.
- 긴 변은 기본 1280px 이하로 축소한다.
- 마스크는 이미지 경계 안에서만 이동·확대되게 제한한다.
- 얼굴 좌표와 마스크 좌표는 해당 로컬 임시 글에서만 사용한다.
- 얼굴 크롭, 얼굴 임베딩, 회원 식별값은 생성하거나 저장하지 않는다.
- 편집본은 생성 시각부터 5일 후 만료된다.
- 앱 시작과 임시 글 목록 조회 시 만료된 편집본을 정리한다.
- 자동 감지는 보조 기능이며 게시 전 사용자가 직접 확인해야 한다.

HEIC/HEIF 파일은 `heic2any`로 JPEG Blob으로 변환한 뒤 동일한 Canvas 처리 경로를 탄다. 변환에 실패하면 해당 사진만 실패 상태로 남기고 JPEG/PNG로 다시 선택하라는 구체적인 안내를 표시한다.

자동 얼굴 감지는 `@mediapipe/tasks-vision`의 Face Detector를 사용한다. WASM과 모델 파일은 앱과 함께 제공하고 편집 화면 진입 시 지연 로드한다. 모델 초기화나 추론이 실패하면 오류를 기록하되 수동 얼굴 추가 기능을 즉시 제공해 작업을 막지 않는다.

## 10. 로컬 AI 동작

`LocalAIProvider`는 네트워크 요청 없이 메모, 톤, 글쓰기 방식, 사진 수, 대표 사진, 사진별 간단 설명을 사용해 구조화된 결과를 만든다.

- 같은 입력은 같은 결과를 반환해 테스트가 안정적이어야 한다.
- 네이버와 인스타그램 결과의 문체와 길이는 분명히 달라야 한다.
- 피할 내용은 결과에서 제거하고 꼭 포함할 내용은 포함한다.
- 부분 재작성은 선택된 섹션만 바꾸고 나머지 결과는 유지한다.
- 의학적 단정 후보와 금지 표현은 규칙 검수 결과에 표시한다.
- 개발 모드임을 결과 화면에 명확히 보여 실제 AI 결과와 혼동하지 않게 한다.

## 11. 상태와 오류 처리

각 비동기 작업은 `idle`, `loading`, `success`, `partial-success`, `error`를 갖는다. 앱 전체 오류 하나로 모든 단계를 덮지 않고 이미지별, 채널별, 저장별 오류를 독립적으로 보존한다.

- 이미지 처리 실패: 성공한 이미지 유지, 실패한 이미지만 재시도
- 얼굴 감지 실패·미지원: 수동 추가로 계속 진행
- 채널 생성 일부 실패: 성공 결과 표시, 실패 채널만 재시도
- 저장 실패: 메모리 상태 유지, 배너 표시, 수동 재시도
- 클립보드 실패: 선택 가능한 텍스트 영역과 안내 제공
- 새로고침·종료: 마지막 유효 단계로 복원
- 오프라인: 로컬 기능은 계속 제공하고 네트워크 어댑터가 활성화된 경우에만 연결 필요 표시

## 12. 디자인 시스템

제공된 `ap-yoga-content-studio-icon.svg`와 `icon-direction.json`의 색을 초기 토큰으로 사용한다.

- 배경 `#F6F1E8`
- 기본 텍스트·선 `#2B2B2B`
- 강조 꽃잎 `#E7B98A`
- 보조 꽃잎 `#F0D7B5`
- 표면 `#FFFFFF`

컴포넌트는 A.P YOGA 이름의 작은 primitive로 만든다. Astryx의 실제 패키지나 컴포넌트를 설치하지 않는 동안 `AstryxButton` 같은 이름을 발명하지 않는다. 토큰 변수와 component props를 분리해 실제 Astryx 토큰으로 치환 가능하게 한다.

모바일 기준 최소 터치 영역은 44px로 하고, 주요 완료 버튼은 화면 하단에 고정되는 `BottomActionBar` 안에 둔다. 데스크톱에서는 최대 너비를 제한해 모바일 작업 흐름이 과도하게 늘어나지 않게 한다.

## 13. 테스트 전략

### 단위 테스트

- 이미지 크기 계산과 만료 시각
- 사진 순서와 대표 사진 불변식
- 공통 브리프 생성
- 채널별 출력 형태
- 부분 재작성 시 비선택 섹션 보존
- 금지 표현과 의학적 단정 규칙
- 5일 만료 정리

### 컴포넌트 테스트

## 14. 완료 기준

MVP는 다음을 모두 만족할 때 완료된다.

- 개발자가 한 명령으로 설치하고 로컬 서버를 실행할 수 있다.
- 데모 데이터 없이 사용자가 자신의 사진으로 전체 흐름을 완료할 수 있다.
- 사진 분석 단계는 한 번만 수행되고 부분 재작성에는 이미지를 다시 사용하지 않는다.
- 네이버와 인스타그램 생성은 독립적으로 성공·실패한다.
- 마스크 편집본만 다음 단계와 저장소에 전달된다.
- 새로고침 후 작성 중 상태가 복구된다.
- 이미지 만료 시각이 표시되고 5일 이후 정리된다.
- 복사 기능이 지원 환경에서 동작하고 실패 대체 UI가 있다.
- 단위·컴포넌트·핵심 사용자 흐름 테스트가 통과한다.
- 프로덕션 빌드가 성공하고 PWA manifest·아이콘이 포함된다.
- README에 현재 로컬 어댑터 범위와 실제 Cloudflare/OpenAI 연결이 후속 작업임을 명시한다.
