# 사진 기반 감성 콘텐츠 생성 설계

작성일: 2026-07-14  
상태: 사용자 승인(대안 1: 감성 변환 + 사진 연관성 유지)

## 배경

현재 생성 결과는 사진 속 장면을 인식하고 글과 연결할 수 있지만, `첫 번째 사진에는 …`처럼 장면을 직접 설명하는 문장이 최종 발행용 콘텐츠에 노출될 수 있다. 사용자는 생성된 글을 곧바로 네이버 블로그와 인스타그램에 발행하므로, 사진 분석 결과를 보고서처럼 나열하기보다 사진에서 느껴지는 빛, 색감, 공간, 소품과 분위기를 자연스러운 감성 서사로 바꿔야 한다.

사진 분석 자체는 정확성 확인에 유용하므로 중간 단계의 `AI가 이해한 내용` 화면에는 유지한다. 최종 결과에서는 원본 장면 설명을 숨기고, 사진과 연결된 발행용 글만 제공한다.

## 목표

- 업로드된 사진과 연관된 구체적인 단서를 최종 글에 유지한다.
- 사진 장면을 순서대로 설명하거나 분석 보고서처럼 나열하지 않는다.
- 네이버 블로그와 인스타그램에 바로 사용할 수 있는 감성적인 문체를 생성한다.
- 사용자가 사진과 메모 분석 진행 상태를 즉시 알 수 있게 한다.
- 사진과 최종 문구의 관계는 썸네일과 배치 순서로 쉽게 확인하게 한다.

## 제외 범위

- 사진 블러 처리 또는 사진을 가리는 별도 단계는 다시 도입하지 않는다.
- 중간 확인 화면의 사진 분석 문장은 제거하지 않는다.
- 새로운 로그인, 계정 또는 저장소 기능은 추가하지 않는다.
- 생성된 콘텐츠를 네이버나 인스타그램에 자동 발행하지 않는다.

## 사용자 흐름

1. 사용자가 사진을 업로드하고 메모를 입력한다.
2. `AI 이해 내용 만들기`를 누르면 버튼이 비활성화되고 `사진과 메모 분석 중…`으로 바뀐다.
3. 화면에는 작업이 끝날 때까지 `사진과 메모를 분석하고 있어요…` 토스트가 유지된다.
4. 분석이 완료되면 `AI가 이해한 내용` 화면에서 사진별 썸네일과 장면 분석을 확인한다.
5. 완료 토스트 `사진 분석이 완료됐어요`가 표시된다.
6. 사용자가 콘텐츠를 생성하면 최종 결과에는 장면 설명을 그대로 복사하지 않은 감성적인 발행용 글이 표시된다.
7. 최종 사진 매칭 영역에는 썸네일과 삽입 위치를 표시하되, 원본 장면 설명은 본문에 노출하지 않는다.

## 생성 규칙

### 서버 AI 생성

- 사진 분석의 핵심 단서 가운데 최소 두 개 이상을 최종 글에 자연스럽게 반영한다.
- 색감, 빛, 재질, 공간, 동작, 소품을 감정과 경험으로 연결한다.
- `사진 1`, `1번째 사진`, `첫 번째 사진에는`, `다음 사진은` 같은 순서형 장면 나열을 금지한다.
- 장면 분석 문장을 그대로 복사하지 않고 발행용 서사로 재구성한다.
- 네이버 결과는 기존 최소 길이와 구조를 유지한다.
- 인스타그램 결과는 짧더라도 사진의 분위기와 수련 경험이 연결되도록 작성한다.

예시 변환:

- 분석 정보: `창가의 흰 꽃과 부드러운 아침 햇살`
- 피해야 할 결과: `첫 번째 사진에는 창가의 흰 꽃과 아침 햇살이 담겼습니다.`
- 원하는 결과: `창가로 번진 부드러운 빛처럼, 오늘의 호흡도 서두르지 않고 천천히 몸 안으로 스며들었습니다.`

### 생성 결과 검증

- 기존 사진 연관성 검사를 유지해 사진과 동떨어진 일반 문구를 막는다.
- 순서형 사진 설명 표현이 발견되면 결과를 유효하지 않은 것으로 처리하고 재생성을 유도한다.
- 배치용 내부 캡션은 사진 매핑과 접근성 정보로 사용할 수 있지만 사용자에게 장면 설명 텍스트로 노출하지 않는다.

### 로컬 대체 생성

- API 실패 시 사용하는 로컬 생성기도 같은 원칙을 따른다.
- 사진 설명 전체를 번호와 함께 붙이지 않고, 분석된 시각 단서와 전체 분위기를 감성 문단에 분산해 사용한다.
- 두 채널 모두 사진과 관련된 구체성은 유지하되 장면 목록 형식을 사용하지 않는다.

## 화면 설계

### 중간 확인 화면

- 기존 사진별 썸네일과 AI 장면 분석을 그대로 유지한다.
- 사용자는 여기에서 AI가 사진을 올바르게 이해했는지 확인한다.

### 최종 결과 화면

- 사진 매칭 카드에는 썸네일과 `문단 N 뒤` 같은 배치 정보만 표시한다.
- 사용자에게 보이는 장면 설명 문단은 제거한다.
- 이미지의 대체 텍스트 등 접근성에 필요한 정보는 유지한다.
- 재작성 버튼 `사진 설명 늘리기`는 `사진 분위기 더하기`로 변경한다.
- 해당 재작성 요청도 장면 나열이 아닌 감성적인 시각 단서 강화를 지시한다.

### 분석 진행 상태

- 메모 제출 직후 분석 전용 로딩 토스트를 표시한다.
- 분석 토스트는 자동으로 사라지지 않고 성공 또는 실패 시점에 교체한다.
- 분석 중 중복 제출을 막기 위해 메모 제출 버튼을 비활성화한다.
- 분석 성공 시 완료 토스트로 교체한다.
- 분석 실패 시 로딩 토스트를 제거하고 기존 오류 표시를 유지한다.

## 상태 및 오류 처리

- 별도의 전역 상태를 만들지 않고 현재 실행 상태를 메모 폼의 `busy` 속성으로 전달한다.
- 토스트 함수는 자동 종료형과 명시적으로 해제하는 지속형을 모두 지원한다.
- 빠른 성공이나 실패에서도 이전 타이머가 새 토스트를 지우지 않도록 기존 타이머를 정리한다.
- 분석 중 버튼 재클릭과 Enter 중복 제출을 모두 막는다.

## 테스트 전략

구현은 테스트 주도 방식으로 진행한다.

1. 서버 생성 검증 테스트에 순서형 사진 나열 거부 사례를 먼저 추가한다.
2. 로컬 생성 결과가 번호형 장면 설명을 포함하지 않고 시각 단서를 사용하는지 테스트한다.
3. 최종 사진 카드에서 장면 설명이 보이지 않고 썸네일·배치 정보가 유지되는지 컴포넌트 테스트한다.
4. 분석 중 지속 토스트, 비활성 버튼, 변경된 버튼 문구를 생성 흐름 테스트에서 확인한다.
5. 재작성 버튼 이름과 지시문 변경을 단위 테스트한다.
6. 전체 단위·컴포넌트 테스트와 핵심 E2E 흐름을 실행한다.
7. Cloudflare 배포 후 실제 사진 업로드부터 결과 생성까지 운영 환경에서 확인한다.

## 완료 기준

- 최종 콘텐츠에 원본 장면 설명이 별도 문장으로 노출되지 않는다.
- 최종 콘텐츠에 순서형 사진 나열 표현이 없다.
- 콘텐츠에는 업로드된 사진에서 추출한 시각적 단서가 자연스럽게 포함된다.
- 사진 분석 중 지속 토스트와 비활성 버튼이 동작한다.
- 중간 확인 화면에서 사진별 분석을 계속 확인할 수 있다.
- 최종 결과의 썸네일과 글 배치 관계를 확인할 수 있다.
- 자동 테스트와 운영 배포 검증이 모두 통과한다.
